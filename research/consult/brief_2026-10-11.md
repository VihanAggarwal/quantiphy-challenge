# QuantiPhy Challenge: how do we get from ~0.80 to 0.90 MRA? (consultation brief)

You are advising a team in the QuantiPhy Challenge (NeurIPS 2026 competition, Track A: any model allowed).
Please think hard and be concrete, critical and quantitative. We want ideas we have NOT already tried, ranked by
expected MRA gain per unit of effort/cost, each with a cheap way to validate it before spending uploads.

## Task

Each test question gives one short video (1-10 s), a "prior" (one exactly-true physical quantity of one object in
the video, e.g. "diameter of the tennis ball = 6.7cm", "speed of the bike = 24m/s", "acceleration of the spacecraft
at 1.0s = 4m/s^2", "Gravity acc = 9.8m/s^2"), and for 3D videos "depth_info" (object-to-camera distances, sometimes
at given times). The question asks another quantity in a stated unit: a size (length/width/height/diameter), a
distance between objects, a speed at time t, or an acceleration at time t. Examples:

- S2 simulation: prior "diameter of one chinese chess = 0.097m"; Q "What is the acceleration of the moving chess at time 1s in m/s^2?"
- S2 internet: prior "width of the mouse = 57mm"; Q "What is the width of the grey notebook in cm?"
- D2 internet: prior "average speed of the person riding scooter = 2.07 m/s"; Q "What is the height of the green car in meters?"
- D2 simulation: prior "speed of the bike = 24m/s"; Q "What is the width of the blue car in meters?"
- D2 simulation: prior "acceleration of the spacecraft at 1.0s = 4m/s^2"; Q "What is the speed of the spacecraft at 1.0s in m/s?"
- S3 simulation (segmented twin): prior "height of the person = 1.75m"; Q "What is the width of the rock in meters?"
- S3 lab: prior "diameter of the tennis ball = 6.7cm"; Q "What is the velocity of the white ball at 1.6s in cm/s?"
- D3 lab: prior "Gravity acc = 9.8m/s^2"; Q "What is the velocity of the yellow toy at 0.60s in cm/s?"
- D3 lab: prior "t=1.0, book acceleration = 2.8m/s^2"; Q "What is the length of the book in cm?"

## Metric

Mean Relative Accuracy per item: thresholds theta in {0.1, 0.2, ..., 0.9, 0.95}; an item gets the fraction of
thresholds with |pred - gt| / gt < 1 - theta. So <5% error = 1.0, 5-10% = 0.9, 10-20% = 0.8, 20-30% = 0.7,
..., 80-90% = 0.1, >=90% = 0 (a 2x overestimate scores 0).
Item scores are averaged within each of 4 categories (S2, D2, S3, D3), then the 4 category means are averaged.
S = static prior (a size), D = dynamic prior (speed or acceleration); 2 = 2D video (planar motion, side view), 3 = 3D.

## Facts we established about the data

- Lab videos: fixed camera, focal ~722 px at 1280 px width; captured at 25 fps and converted to 24 fps by frame drops.
  Lab clips come in families (captured_X, X s, X x = same event with replaced backgrounds; several camera views).
  Measured with f and depth_info, stated lab priors are consistent (speeds ratio 1.00, sizes 0.94 because of blur).
- 3D simulation cameras are NOT fixed (hfov 8-103 deg, varies across cameras of the same scene).
- ~60 "scene families" (twins, multi-camera views, same scene) cover 1723 questions; a family clip's prior can
  answer another clip's question exactly, and answers about the same object can be pooled across clips.
- Some labels are clearly wrong/noisy (validation has ~12 suspect items out of 159); some questions ask about times
  beyond the clip end (trimmed clips).

## Our pipeline (Track A)

1. Claude Opus 5.5 (high reasoning) sees 16 uniform frames + frames at every mentioned time (max 32, 854 px long
   edge, each labelled with frame index and time) and all of the video's questions in one request. It returns
   question specs (which object/dimension/time), pixel annotations (points/boxes/segments on frames, i.e. tracks)
   and its own direct numeric answer per question.
2. A geometry solver turns the pixel tracks + prior (+ depth_info, + a focal estimate in 3D) into an answer
   (2D: scale = prior / prior_pixels; speeds from fitted tracks; 3D: pinhole with depth). Optional CPU refinements
   (optical-flow prior refinement, GrabCut/template dense tracking) mostly did not help.
3. Routing: 2D -> geometry answer; 3D non-lab -> Claude's direct answer (geometry was much worse there);
   lab 3D -> geometry for sizes, direct for motion.
4. Model-free post-rules: twin copy (segmented copy takes the original clip's answer), stated facts transferred
   within scene families, per-clip scale correction of direct 3D-sim answers from family facts, pooling the same
   object across family clips, pooling lab prop sizes, a 3-run median of Claude direct answers on 3D non-lab clips.

## What we tried that did NOT help (or helped little)

- Combining Claude runs by median on 2D (no gain; it does help on 3D non-lab: +0.02 per question).
- GPT-6 Astra direct answers on the same frames: on validation .747 vs Claude .757; answers highly correlated with
  Claude's (median |log ratio| 0.045); no ensemble gain.
- Geometry instead of direct on 3D non-lab (much worse: -0.09 to -0.13 per answer).
- Optical-flow refinement of the prior's pixel speed (lags on large/articulated movers; turned off: +0.025 D2).
- Dense CPU tracking (GrabCut + templates) for sizes: slightly negative; for motion ~neutral.
- Re-measuring object extents by Claude on zoomed full-resolution crops: within-5% extents .736 -> .826 against
  pixel-exact masks, but only ~+0.003 MRA modelled.
- Claude agent loop with measurement tools (medium effort): not better than one high-effort annotation, 4x cost.
- Higher reasoning effort (xhigh) was worse on validation than high.
